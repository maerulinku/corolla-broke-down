== Цель работы

Продолжить рефакторинг программы управления светодиодами: выделить режим работы в
самостоятельную сущность (интерфейс `IMode` + классы-режимы), собрать режимы в массив и
переключать их автоматически по времени. В результате главный цикл программы должен занимать
несколько строк, а добавление нового светодиода или нового режима — не требовать правки
`main()`.

== Что было сделано на предыдущем этапе

На прошлой лекции «лапшекод» (последовательные `GPIOC::ODR::ODR5::High::Set()` на каждый
светодиод) был заменён на классы с интерфейсами:

* `IPin` / `Pin` — «ножка» порта: установить в единицу, сбросить, переключить, получить
  состояние;
* `ILed` / `Led` — светодиод, который принимает в конструктор `IPin&` и делегирует ему
  вызовы;
* массив `std::array<IPin*, N>` и один цикл `for (auto pin : pins) pin->Toggle();`.

В результате логика управления светодиодами сократилась до 2–3 строк. Использовался
`std::array` вместо обычного C-массива: у него известен размер на этапе компиляции, он не
превращается в «голый указатель» при передаче и не позволяет выйти за границы массива.

== Постановка задачи

Программа должна сама переключать режимы работы светодиодов:

[cols="1,2",options="header"]
|=====================
|Режим |Что делает
|*ModeBlink* |все светодиоды включаются одновременно и одновременно выключаются
|*ModeTree* (ёлочка) |светодиоды по очереди зажигаются, «бегущий огонь»
|*ModeChess* (шахматка) |загораются чётные светодиоды, затем нечётные
|=====================

Каждый режим работает 10 секунд, затем программа переключается на следующий.

== Теоретическая часть

=== Интерфейс (контракт)

Интерфейс — это абстрактный класс с чисто виртуальными функциями. Он описывает, *что*
умеет сущность, но не содержит реализации. Класс, наследующий интерфейс, обязан
переопределить все его методы.

=== Полиморфизм

`IMode` позволяет обращаться ко всем режимам одинаково: у каждого есть `Init()` и `Work()`.
Хранение режимов в массиве указателей на базовый интерфейс `std::array<IMode*, N>` позволяет
вызывать метод того режима, на который в данный момент указывает индекс, без `if`/`switch`
и без знания конкретного класса.

=== Роль методов Init() и Work()

* `Init()` — приводит режим в начальное состояние при переключении. Без этого каждый
  следующий запуск режима начинается не с начала (в прошлой версии ёлочка «пропускала»
  первые светодиоды после переключения).
* `Work()` — выполняет один шаг работы режима. Время между шагами задаётся задержкой в
  главном цикле.

Пара «интерфейс + несколько реализаций» — это, по сути, паттерн *Стратегия*: алгоритм
(режим) подменяется во время работы программы.

=== Интерфейс IMode

[source,cpp]
----
#ifndef UNTITLED2_CONTRACTS_IMODE_H
#define UNTITLED2_CONTRACTS_IMODE_H

class IMode
{
public:
    virtual ~IMode() = default;

    virtual void Work() = 0;
    virtual void Init() = 0;
};

#endif // UNTITLED2_CONTRACTS_IMODE_H
----

=== Интерфейс ILed

[source,cpp]
----
class ILed
{
public:
    virtual void Light() = 0;   // зажечь
    virtual void PutOut() = 0;  // потушить
    virtual void Toggle() = 0;  // переключить

    virtual ~ILed() = default;
};
----

=== Режим ModeBlink (моргание всеми светодиодами)

Класс принимает массив светодиодов и в `Work()` переключает их все сразу:

[source,cpp]
----
template <std::size_t Size>
class ModeBlink final : public IMode
{
public:
    explicit ModeBlink(const std::array<ILed*, Size>& leds)
        : leds(leds)
    {
    }

    void Init() override
    {
        for (ILed* led : leds)
        {
            led->Light();
        }
    }

    void Work() override
    {
        for (auto led : leds)
        {
            led->Toggle();
        }
    }

private:
    const std::array<ILed*, Size>& leds;
};
----

=== Режим ModeTree (ёлочка)

Здесь `Work()` делает один шаг: переключает светодиод с номером `step`, после чего
увеличивает `step`. Когда номер дошёл до конца массива, он сбрасывается в ноль — так
получается «бегущий огонь»:

[source,cpp]
----
template <std::size_t Size>
class ModeTree final : public IMode
{
public:
    explicit ModeTree(const std::array<ILed*, Size>& leds)
        : leds(leds)
        , step(0U)
    {
    }

    void Init() override
    {
        for (auto led : leds)
        {
            led->Light();
        }
        step = 0U;
    }

    void Work() override
    {
        if (step == Size)
        {
            step = 0;
        }
        leds[step]->Toggle();
        ++step;
    }

private:
    const std::array<ILed*, Size>& leds;
    std::size_t step;
};
----

=== Режим ModeChess (шахматка)

В шахматном режиме светодиоды делятся на две группы по чётности индекса: сначала горят
светодиоды с чётными индексами, затем — с нечётными. Номер группы хранится в поле `phase`
и переключается на каждом шаге:

[source,cpp]
----
template <std::size_t Size>
class ModeChess final : public IMode
{
public:
    explicit ModeChess(const std::array<ILed*, Size>& leds)
        : leds(leds)
        , phase(0U)
    {
    }

    void Init() override
    {
        for (auto led : leds)
        {
            led->PutOut();
        }
        phase = 0U;
    }

    void Work() override
    {
        for (std::size_t i = 0U; i < Size; ++i)
        {
            if ((i % 2U) == phase)
            {
                leds[i]->Light();
            }
            else
            {
                leds[i]->PutOut();
            }
        }
        phase = (phase + 1U) % 2U;
    }

private:
    const std::array<ILed*, Size>& leds;
    std::size_t phase;
};
----

=== main.cpp

Все светодиоды привязываются к пинам, затем собираются в массив `leds`. Режимы получают
этот массив и складываются в массив режимов `modes`. В главном цикле режим работает
заданное число шагов, после чего номер режима увеличивается по модулю количества режимов,
а у нового режима вызывается `Init()`:

[source,cpp]
----
#include <array>
#include "rccregisters.hpp"     // for RCC
#include "gpioaregisters.hpp"   // for GPIOA
#include "gpiocregisters.hpp"   // for GPIOC
#include "Pin.h"                // for Pin
#include "Led.h"                // for Led
#include "ModeBlink.h"          // for ModeBlink
#include "ModeTree.h"           // for ModeTree
#include "ModeChess.h"          // for ModeChess

Pin<GPIOC::ODR,5> pin5;
Pin<GPIOC::ODR,8> pin8;
Pin<GPIOC::ODR,9> pin9;
Pin<GPIOA::ODR,5> pin5a;

Led led1(pin5);
Led led2(pin8);
Led led3(pin9);
Led led4(pin5a);

constexpr std::uint32_t ledsCount = 4U;
std::array<ILed*, ledsCount> leds = {&led1, &led2, &led3, &led4};

ModeBlink<ledsCount> modeBlink(leds);
ModeTree<ledsCount>  modeTree(leds);
ModeChess<ledsCount> modeChess(leds);

constexpr std::uint32_t modesCount = 3U;
std::array<IMode*, modesCount> modes = {&modeBlink, &modeTree, &modeChess};

constexpr std::uint32_t DELAYS_PER_10S = 100U;

int main(void)
{
  RCC::AHB1ENR::GPIOAEN::Enable::Set();
  RCC::AHB1ENR::GPIOCEN::Enable::Set();

  GPIOA::MODER::MODER5::Output::Set();
  GPIOC::MODER::MODER5::Output::Set();
  GPIOC::MODER::MODER8::Output::Set();
  GPIOC::MODER::MODER9::Output::Set();

  std::uint32_t modeNumber = 0U;

  while (1)
  {
    for (std::uint32_t i = 0U; i < DELAYS_PER_10S / ledsCount; ++i)
    {
      modes[modeNumber]->Work();
      delay(1000000);
    }

    modeNumber = (modeNumber + 1U) % modesCount;
    modes[modeNumber]->Init();
  }
}
----

== Переключение режимов

Переключение построено на трёх величинах:

* `DELAYS_PER_10S` — условное число задержек, соответствующее десяти секундам;
* `ledsCount` — количество светодиодов (число шагов, которое успевает сделать режим);
* `modesCount` — количество режимов в массиве.

Внутренний цикл `for` даёт режиму сделать положенное число шагов, после чего строка

[source,cpp]
----
modeNumber = (modeNumber + 1U) % modesCount;
----

переводит номер на следующий режим, а `modes[modeNumber]->Init();` приводит новый режим в
начальное состояние. Деление по модулю `modesCount` (вместо жёстко прописанного числа)
позволяет менять количество режимов в одном месте — в константе `modesCount`.

[NOTE]
====
Слово «десять секунд» здесь условно: `delay()` — это пустой цикл, длительность которого
зависит от тактовой частоты. Точный отсчёт времени появится после подключения системного
таймера. Зато добавление третьего режима не меняет ни одной строки главного цикла.
====

== Результат работы

[cols="1,2",options="header"]
|=====================
|Было |Стало
|90+ строк «лапшекода» на каждый светодиод |6 строк логики в `main()`
|Новый светодиод — переписать весь код |Добавить объект в массив `leds`
|Новый режим — новый `if`/`else` в `main()` |Написать класс режима и добавить в `modes`
|Смена порта — правка во всех строках |Правка одной строки объявления `Pin`
|=====================

При добавлении четвёртого светодиода меняется только объявление и массив `leds`, а весь
алгоритм работы программы остаётся без изменений.

== Замечания по реализации

* В классе `Pin` метод `Reset()` пока не реализован (заглушка), поэтому `Led::PutOut()`
  фактически ничего не делает. Из-за этого в `ModeBlink` и `ModeTree` в `Init()`
  используется `Light()`, а работу с «выключением» обеспечивает `Toggle()`.
  Для полноценного `ModeChess` (и для корректного `PutOut()`) `Reset()` нужно реализовать —
  например, через `TPort::Write(TPort::Get() & ~(1U << pinNum))`, так как готового метода
  `Reset` у регистра нет.
* В интерфейсе `IPin` нет виртуального деструктора, поэтому удаление объекта через указатель
  на `IPin` было бы некорректным. Для текущей программы это не критично (объекты статические
  и не удаляются), но по правилам деструктор `virtual ~IPin() = default;` стоит добавить.
* В текущей версии `main()` метод `Init()` вызывается для *нового* режима после
  переключения; для самого первого режима `Init()` не вызывается ни разу, что компенсируется
  тем, что регистры `ODR` после сброса и так обнулены.

== Выводы

В ходе работы код программы был переведён на архитектуру с интерфейсами и динамическим
полиморфизмом: `IPin`/`Pin`, `ILed`/`Led`, `IMode`/`ModeBlink`, `ModeTree`, `ModeChess`.
Режимы собраны в массив `std::array<IMode*, N>` и переключаются автоматически по счётчику,
а их начальное состояние задаётся методом `Init()`.

Главный результат — *расширяемость*: добавление светодиода сводится к добавлению объекта в
массив, добавление режима — к написанию нового класса и добавлению его в массив режимов,
при этом `main()` остаётся неизменным. Логика работы программы сократилась с десятков строк
до шести строк главного цикла, а код стал читаемым и предсказуемым.
