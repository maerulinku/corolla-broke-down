:description: Отчёт по лекции 1 — знакомство с IAR Embedded Workbench и управление светодиодом.

На первой лекции мы познакомились со средой разработки *IAR Embedded Workbench for Arm*,
создали первый проект для микроконтроллера *STM32F411RE*, запустили его в симуляторе и на
реальной плате, а затем написали и пошагово разобрали программу управления светодиодами.

== Создание проекта

Проект создаётся через меню *Project ⇒ Create New Project*, шаблон — *C++ ⇒ main*.

[IMPORTANT]
====
Путь к проекту не должен содержать русских букв — IAR плохо работает с кириллицей
(с этим уже сталкивались при установке лицензии). Проекты рекомендуется хранить, например,
в папке `C:\Work`, а каждый проект — в отдельной подпапке (`Lab0`, `Lab1`, ...). Называть
папки и проекты нужно понятно, иначе через неделю не вспомнить, что там лежит.
====

== Рабочее пространство (workspace)

При первом запуске отладки IAR просит сохранить *рабочее пространство* (workspace). Это
контейнер, в котором может лежать несколько проектов (например, все лабораторные работы).
Добавить уже существующий проект в workspace можно через *Project ⇒ Add Existing Project*.

== Настройка редактора

Чтобы в редакторе отображались номера строк:
*Tools ⇒ Options ⇒ Editor ⇒ Show line numbers*.

== Первый запуск в симуляторе

По умолчанию программа собирается и выполняется в *симуляторе* выбранного микроконтроллера.
Запуск производится кнопкой отладки (Play), сборка — `Ctrl-F7`.

Полезные действия в режиме отладки:

* пошаговое выполнение — `F10` (шаг по коду C++); если встать на окно ассемблера, шаги будут
  идти уже по ассемблерным командам;
* сброс — кнопка Reset;
* *View ⇒ Registers* — окно регистров процессора: счётчик команд *PC* (program counter) и
  указатель стека *SP* (stack pointer).

По умолчанию симулятор загружен с настройками «какого-то» процессора (счётчик команд стоит не
на том адресе). Это исправляется выбором нужного микроконтроллера.

== Выбор микроконтроллера

Модель выбирается в свойствах проекта: правой кнопкой по проекту ⇒ *Options ⇒ General Options
⇒ Target ⇒ Device* и далее *ST ⇒ STM32F4 ⇒ STM32F411 ⇒ STM32F411RE*.

[NOTE]
====
`RE` и `RC` — фактически одна и та же модель, отличаются только корпусом.
После выбора микроконтроллера счётчик команд `PC` встаёт на правильный адрес `0x08000000`.
====

== Конфигурация линкера (файл *.icf)

Файл линкера (`stm32f411xE.icf`) открывается через *Options ⇒ Linker ⇒ Config ⇒ Edit*.
В нём прописано, как линкер должен размещать код и данные в памяти микроконтроллера.

Основные величины:

* адрес старта программы — `0x08000000`: при запуске микроконтроллера в `PC` по умолчанию
  записывается этот адрес; здесь же расположена таблица векторов прерываний — первое слово это
  указатель стека, второе — адрес функции инициализации переменных (сначала нулями, затем
  инициализированными значениями);
* память программ (flash/ROM) — `0x08000000 … 0x0807FFFF`;
* ОЗУ (RAM) — `0x20000000 … 0x2001FFFF`;
* размер стека (по умолчанию `0x2000`) и размер кучи.

Правила размещения, которые линкер берёт из этой конфигурации:

* инициализируемые переменные размещаются в секции *read/write* (то есть в ОЗУ);
* всё, что лежит в ROM, — *read only* (туда нельзя писать);
* всё, что лежит в RAM, — *read/write*, там же находятся стек и куча.

Стек при этом выровнен по 8 байтам: его адрес должен заканчиваться на кратное восьми значение.

== Отладчик: симулятор и ST-Link

По умолчанию в настройках отладчика стоит драйвер *Simulator* — программа «прошивается» в
симулятор, а не в реальную плату. Для работы с реальной платой нужно:

. В *Options ⇒ Debugger ⇒ Driver* выбрать *ST-Link*.
. В настройках ST-Link проверить, что выбран интерфейс *SWD* (это интерфейс отладки).
. Подключить плату по USB и установить драйверы, после чего проверить появление устройства
  *STM32 ST-Link* в диспетчере устройств.

Признаки состояния платы:

* если плата не определилась, на ней горит дополнительный красный светодиод;
* после успешного запуска программы горит зелёный светодиод;
* ошибка `no MCU device found` обычно означает проблемы с подключением или драйвером —
  стоит проверить соединение (переходник может быть вставлен «вверх ногами») и драйвер.

== Программа управления светодиодом

В качестве примера мы собрали и запустили программу, которая зажигает и гасит светодиоды.
Светодиоды висят на выводах портов *C (5, 8, 9)* и *A (5)*.

Программа делает три вещи:

. *Подаёт тактирование на порты.* На периферии STM32 тактирование по умолчанию отключено —
   это сделано для экономии энергии. Поэтому для *любого* модуля первым делом нужно включить
   тактирование, иначе модуль не заработает.
. *Настраивает вывод порта на выход* (регистр `MODER`): порт может работать на вход (кнопка)
   или на выход (светодиод).
. *Зажигает и гасит светодиод* через регистр `ODR` (*Output Data Register* — выходной регистр
   данных порта): запись `1` зажигает светодиод, запись `0` гасит.

[source,cpp]
----
RCC::AHB1ENR::GPIOCEN::Enable::Set();  // подать тактирование на порт C
GPIOC::MODER::MODER5::Output::Set();   // настроить вывод C5 как выход
GPIOC::ODR::ODR5::Enable::Set();       // зажечь светодиод (1)
GPIOC::ODR::ODR5::Disable::Set();      // погасить светодиод (0)
----

В режиме отладки биты регистра `ODR` можно менять *вручную*: *View ⇒ Registers ⇒ GPIO C ⇒
ODR* и записать `1` или `0` в нужный бит. Светодиод при этом загорается/гаснет — это наглядно
показывает, что вся работа программы сводится к управлению регистрами: строка кода делает то
же самое, что мы делаем рукой.

[NOTE]
====
Пошагово (клавишей `F10`) можно проследить: сначала загорается один светодиод, затем второй,
потом идёт задержка, после чего они по очереди гаснут.
====

== Задание («ёлочка»)

Задание на отработку: сделать «ёлочку» — *бегущий огонь*. Светодиоды (порт A пин 5 и порт C
пины 5, 8, 9) должны загораться по очереди: первый, второй, третий, четвёртый, а затем гаснуть
в том же порядке, с задержками между переключениями.

[NOTE]
====
Если какие-то светодиоды на плате не работают (порт сгорел или перепаян), задание всё равно
выполняется — правильность можно проверить по изменению битов регистра `ODR` в отладчике.
====
